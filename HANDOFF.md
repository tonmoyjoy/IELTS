# AI handoff: IELTS Practice Studio

Read this first. It explains what the project is, what it looked like before the
hardening pass, what was changed and why, the rules not to break, and what to do
next. Commit `cba51c1` on branch `hardening` contains the whole pass (`main` is
the original). Run `git diff main hardening` for line-level detail.

---

## 1. What the product is

A paid-to-be IELTS Academic practice web app. Users practise four modules:

| Module | How it is scored |
| --- | --- |
| Listening | Server marks answers against hidden keys → estimated band |
| Reading | Server marks answers against hidden keys → estimated band |
| Writing | Gemini AI examiner, 4 official criteria → overall band computed by server |
| Speaking | Gemini hears the audio, 4 official criteria → overall band computed by server |

The owner plans to publish it and add payments. A `free`/`pro` plan system with
daily AI quotas already exists; payments only need to set `user.plan`.

**Stack:** Next.js 16.4 (App Router, Turbopack, `src/proxy.ts` replaces
middleware), React 19, TypeScript strict, Tailwind 4, MongoDB + Mongoose 9,
`@google/genai` (Gemini), Zod 4, Vitest 5, Playwright 1.63, optional Sentry.

> Next.js 16 differs from older training data. Read the relevant guide in
> `node_modules/next/dist/docs/` before changing framework-level code
> (see `AGENTS.md`). Examples: `proxy.ts` not `middleware.ts`; `params` and
> `searchParams` are Promises; `PageProps<"/route">` / `RouteContext<...>`
> are global types generated by `next typegen`.

## 2. State BEFORE the hardening pass (original `main`)

Reviewed at **5/10**. Builds, but not shippable. Critical problems:

1. `forgot-password` and `register` returned reset/verification URLs in the API
   response when email wasn't configured → anyone could take over any account.
2. Reading/listening scores computed in the browser and trusted by the server;
   `rawScore` not bounded (score could exceed 9 → 500 errors).
3. Essay/transcript inserted straight into the AI prompt → prompt injection
   could set the band. Client also sent the task prompt itself.
4. All three listening sets played the same MP3 with different questions; only
   23 questions in total.
5. Recording duration came from the client (uploads were faked as 30 s); rate
   limit keyed on spoofable `x-forwarded-for[0]`.

Also: no session revocation, open redirect on `/login?from=//evil`, email
enumeration on register, 1 E2E test that mocked the only AI call, no CI, no
Docker, Google Fonts fetched at build time, fake UI (hard-coded "Target 8.0",
dead toolbar buttons), Task 1 charts never shown to the student, deprecated
`@google/generative-ai` SDK, critical CVE in Next.js.

## 3. What was changed (by area)

### Security / auth (`src/server/auth`, `src/server/services/auth.ts`, `src/app/api/auth/*`)
- Links only ever sent by email (`server/email/*`, Resend or console transport).
- Register / forgot / resend return identical responses whether or not the
  account exists; dummy bcrypt on unknown emails (timing).
- Must verify email before login (`EMAIL_NOT_VERIFIED`, resend endpoint).
  Verify page needs a button press so link scanners can't consume tokens.
- JWT = `{ sub, tv }` (no email). `tv` (tokenVersion) checked against DB on
  every request in `getSessionUser()`. Password reset increments it → all
  sessions revoked. Reset also marks email verified.
- Cookie: `__Host-ielts_session` when secure, `ielts_session` otherwise.
  "Secure" = production AND `APP_URL` is not `http://` (`server/auth/cookie.ts`).
- CSRF: `assertSameOrigin()` (Origin allowlist from `APP_URL`/`ALLOWED_ORIGINS`/
  Vercel vars, or `Sec-Fetch-Site: same-origin`; header-less rejected in prod)
  + JSON-only bodies via `readJson()` (`server/http/*`).
- Rate limits (`server/security/rate-limit.ts`): per-IP and per-email; Upstash
  pipeline `INCR + EXPIRE NX + TTL`, falls back to memory. Client IP from the
  rightmost trusted hop (`TRUST_PROXY_HOPS`) or `CLIENT_IP_HEADER`.
- Nonce CSP + strict-dynamic set in `src/proxy.ts` (`server/security/csp.ts`);
  root layout calls `headers()` so every page renders dynamically (required for
  nonces). Security headers in `next.config.ts`.
- `safeRedirectPath()` in `src/lib/text.ts` fixes the open redirect.
- `server/env.ts`: Zod-validated env, lazy; production refuses to run without
  `MONGODB_URI`, `JWT_SECRET` (32+), `APP_URL`, email config.

### Scoring integrity
- Public content (no answers): `src/content/{reading,listening,writing,speaking}.ts`.
- Server-only answer keys + explanations: `src/server/content/answer-keys.ts`.
  Listening scripts: `src/server/content/listening-scripts.json` (revealed only
  after submission).
- Grading: `src/server/practice/grading.ts` (normalisation, word limits, IELTS
  strict spelling). Bands: `src/lib/bands.ts` (official 40-question tables,
  shorter sets scaled; `roundToHalfBand` .25→.5, .75→next whole).
- `POST /api/practice/attempts` takes `{ module, setId, answers }` only.

### AI (`src/server/ai/*`)
- `@google/genai` 2.32, one client (`client.ts`), timeout 90 s, 1 retry.
- System instruction separate from candidate content; essay wrapped by
  `wrapUntrusted()` (strips tag break-outs); JSON schema output; Zod validated;
  1 retry on malformed output; criteria snapped to half bands; **overall band
  always computed on the server**, never taken from the model.
- Writing: `POST /api/writing/evaluate` takes `{ taskId, answer }`; prompt and
  Task 1 chart data looked up on the server. <50 words rejected before AI.
- Speaking: single multimodal call (audio inline + exam questions), returns
  transcript + criteria. Duration measured server-side
  (`server/audio/duration.ts`: music-metadata + custom WebM cluster scanner for
  Chrome MediaRecorder files with no duration). 30 s – 5 min, ≤10 MB.
  SSE streaming when `Accept: text/event-stream`.
- Provider errors mapped to safe messages (`errors.ts`); no key/quota details leak.
- Default model `gemini-2.5-flash-lite` (`GEMINI_MODEL` overrides).

### Plans and quotas (`src/lib/plans.ts`, `src/server/billing/quota.ts`, `models/Usage.ts`)
- `free`: 3 writing + 3 speaking AI evaluations per UTC day; `pro`: 30 + 30.
- Atomic reservation: conditional `$inc` + unique `(user, day)` index; refunded
  on AI failure. `User.plan` is the only thing payments need to change.

### Data model (`src/server/models`)
- `User`: email, password (bcrypt, select:false), emailVerified, token hashes,
  tokenVersion, plan, targetBand, lastLoginAt.
- `PracticeAttempt`: user, module, contentId, title, score, rawScore,
  totalQuestions, summary, details (server-built), ai metadata, date. Indexed.
- `Usage`: user, day, speaking, writing.
- Removed: `TestResult` model and `User.tests` array (old data is harmless).

### Content
- Reading: 3 passages × 12 questions (TF/NG, Y/N/NG, paragraph matching, MCQ,
  completion). Listening: 3 sets × 10 questions with their own MP3s in
  `public/listening/`, generated offline by `scripts/generate-listening-audio.mjs`
  (espeak-ng + MBROLA voices; robotic but intelligible).
- Writing: 2 × Task 1 (line chart, process diagram) + 3 × Task 2.
- Speaking: 3 topic sets (Part 1/2/3).

### UI (`src/app`, `src/components`)
- Route groups: `(auth)` sign-in flows, `(app)` signed-in area (layout checks session).
- Pages: `/dashboard`, `/practice/{listening,reading,writing,speaking}`,
  `/practice/{reading,listening}/[setId]`, `/practice/writing/[taskId]`,
  `/history`, `/history/[id]` (writing revision diff via `diff` package).
- Server components load data directly; client components only for interaction.
- Shared primitives in `src/components/ui.tsx`. Dark mode, mobile, skip link,
  drafts in localStorage, exam-mode listening (play once).
- Old URLs `/writing/*` redirect (`next.config.ts`).

### Ops
- `Dockerfile` (standalone output, non-root, healthcheck), `docker-compose.yml`
  (app + mongo:7), `/api/health`, opt-in Sentry (`src/instrumentation*.ts`),
  `.github/workflows/ci.yml` (lint, typecheck, unit+coverage, audit,
  integration on mongo:7, build + E2E, docker build), `scripts/smoke-auth.mjs`.
- Fonts from the `geist` package (no network at build).
- Upgraded: next 16.4.5, zod 4.6.7, mongoose 9.12 (fixed critical/high CVEs).

## 4. Rules — do not break these

1. **Never trust the client for scores, durations, prompts or plan.** The server
   computes every band.
2. **Never return tokens or links in API responses.** Email only.
3. **Never put answer keys or listening scripts in client bundles.** Keep them
   under `src/server/content` (they import `server-only`).
4. **Candidate text goes to the AI only through `wrapUntrusted()`**, never in the
   system instruction. Bump `*_PROMPT_VERSION` when changing prompts.
5. **Every mutating route:** `assertSameOrigin(req)` → auth → rate limit →
   `readJson(req, schema)`. Wrap handlers with `handler("name", ...)`.
6. **AI routes:** `reserveQuota` before the call, `releaseQuota` on failure.
7. **Route files (`route.ts`) may only export HTTP methods and route config**
   (e.g. `maxDuration`); Next fails the build otherwise.
8. Use `updateOne` + `matchedCount` rather than `findOneAndUpdate` with projections.

## 5. Testing

| Command | Notes |
| --- | --- |
| `npm test` | 121 unit tests, no DB |
| `npm run test:integration` | 33 tests; real DB via `TEST_MONGODB_URI`, else mongodb-memory-server |
| `npm run build && npm run test:e2e` | 21 Playwright tests vs production build; `E2E_MONGODB_URI` |
| `npm run verify` | lint + typecheck + unit + build |

Gotchas learned:
- `tests/unit/content-integrity.test.ts` validates every question/answer key
  against the passage/script, word limits and audio files. Run it after any
  content edit.
- Vitest 5: use `vi.hoisted` + `mockClear()` with a default implementation; a
  `mockReset()` + throwing mock wrongly fails tests.
- FerretDB (used locally where MongoDB couldn't be installed) is not atomic, so
  the concurrent-quota test auto-skips on it; it runs on real MongoDB in CI.
- E2E requests made with Playwright's `request` need an `Origin` header in
  production mode, or the CSRF guard returns 403.

## 6. Known limitations

- Listening audio is synthetic TTS → replace with real/neural recordings
  (keep scripts identical; answers depend on the text).
- AI scoring was tested only with mocked responses → not yet calibrated.
- Docker image not built in the dev sandbox (the standalone server it runs was tested).
- Logout clears this browser's cookie only (no "sign out everywhere" button yet).
- No account deletion / data export, privacy policy or terms yet.
- Concurrent-quota test has only run against FerretDB (skipped), not real MongoDB.
